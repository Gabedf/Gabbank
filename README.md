# Gabbank

Gabbank is a study-oriented backend project focused on Java and Spring Boot, inspired by financial systems and digital banking concepts.

The goal of the project is to gradually evolve a simple financial backend into a more robust system over time, enabling practical learning about:

- REST APIs
- backend architecture
- domain modeling
- data persistence
- financial transactions
- consistency
- concurrency
- testing
- observability
- security
- scalability
- software engineering best practices

---

# Project Purpose

The main goal of Gabbank is NOT to build a perfect enterprise-grade system from the beginning.

Instead, the project exists primarily as a practical learning platform, built incrementally to allow real engineering problems to emerge naturally as the system grows.

The objective is to learn by:

- building;
- making mistakes;
- refactoring;
- evolving the architecture gradually;
- understanding technical trade-offs;
- avoiding premature complexity.

The idea is to start small while allowing continuous growth as new challenges appear.

---

# Initial Features

At the current stage, the project focuses on basic internal digital wallet functionalities:

- user creation;
- automatic wallet creation;
- deposits;
- withdrawals;
- transfers;
- balance inquiry;
- transaction history.

In the future, the system may evolve to include:

- authentication and authorization;
- auditing;
- idempotency;
- retry/backoff strategies;
- messaging systems;
- caching;
- observability;
- fraud detection;
- distributed processing;
- event-driven architecture;
- external integrations;
- advanced testing;
- scalability and performance improvements.

# Project Philosophy

This project is being developed as part of an ongoing backend software engineering learning journey.

Because of that:

- not every architectural decision will be “optimal” from the beginning;
- some solutions will intentionally remain simple;
- the system is expected to evolve together with the learning process.

The goal is to build real technical understanding instead of simply copying ready-made enterprise architectures.

---

# Artificial Intelligence Usage

Artificial Intelligence tools are used as support during the development process, mainly for:

- idea review;
- requirement refinement;
- architectural discussions;
- concept clarification;
- documentation support;
- technical guidance.

However:

- the project is NOT automatically generated;
- decisions are manually analyzed;
- the code is consciously studied, adapted, and implemented;
- AI is used as a learning and support tool, not as a replacement for software engineering practices.

A major part of this project's purpose is learning through practice — dealing with mistakes, limitations, and real implementation challenges during development.
